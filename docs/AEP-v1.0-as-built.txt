4. MATCH WORKER (as-built)
======================================================================
Lifecycle:
  1. Room dibuat saat JOIN_GAME pertama untuk matchId.
  2. begin(): peserta manusia + bot (kursi kosong), kursi diacak,
     MatchState dibuat dengan serverSeed (crypto.randomBytes), seedHash
     dikirim sejak awal.
  3. Loop berbasis peristiwa: aksi pemain -> afterChange() ->
     schedule() (pasang timer berikut) -> broadcast snapshot ->
     TRICK_RESOLVE bila ada.
State: MatchState murni sinkron; tanpa I/O sehingga mudah dites.
Persistensi: tidak ada. Failover: tidak ada (proses mati = match hilang).
API ke gateway: pemanggilan metode langsung (join, start, action, leave).
Validasi sequenceId/nonce: [BELUM].

Rincian penjadwalan (Room.schedule):
  - Freeze trick dua tahap: kartu ke-4 jatuh -> 1200 ms trump masih
    tertutup -> dibuka bersamaan (TRICK_RESOLVE) -> 2600 ms -> trick
    berikutnya.
  - Fase FINISHED (ronde): lanjut otomatis setelah 30 dtk atau NEXT_ROUND.
  - Giliran bot: botDelayMs lalu applyBotMove.
  - Giliran manusia: batas 25 dtk (turnEndsAt); habis -> autoPlay.
  - 3 timeout beruntun -> aiControlled.
  Snapshot tiap pemain membawa turnMsLeft dan turnMsTotal (relatif).

5. WEBSOCKET & MESSAGING CONTRACT [BERBEDA]
======================================================================
Kontrak asli memakai {op,...} dan {evt,seq,...}. As-built memakai
{type,payload}. Sumber kebenaran: shared/types.ts.

Client -> Server
  { "type": "JOIN_GAME",  "payload": { "matchId": "...", "playerId": "Budi", "token": "..." } }
  { "type": "START_GAME", "payload": { "matchId": "..." } }
  { "type": "PLAYER_ACTION", "payload": { "matchId": "...",
      "action": "BID|PASS|SELECT_TRUMP|PLAY_CARD|NEXT_ROUND|PLAY_AGAIN|CHOOSE_TEAM",
      "data": { "amount": 8, "suit": "S", "cardIndex": 3, "team": "A" } } }
Server -> Client
  { "type": "JOINED", "payload": { "roomId", "playerId", "token" } }
  { "type": "GAME_UPDATE", "payload": GameStateSnapshot }
  { "type": "TRICK_RESOLVE", "payload": { "cards", "starter", "winner", "winningCard" } }
  { "type": "ACTION_ERROR", "payload": { "msg": "..." } }

Kartu ditunjuk lewat cardIndex pada tangan milik server (bukan string
"S:A"). Hidden trump: kartu trump di meja dikirim {suit, rank:'?',
isHidden:true} sampai trick selesai.
Sequence & nonce: [BELUM]. Event "heartbeat" aplikasi: tidak ada, yang
dipakai ping/pong tingkat protokol WebSocket.
Kode penutupan: 4000 = sesi digantikan koneksi baru.

14. RISKS & MITIGATIONS (diperbarui)
======================================================================
1. Pod explosion: tidak relevan sekarang; multiplexing sudah menjadi
   bawaan desain (banyak Room per proses).
2. Single point of failure: SEKARANG state hanya di memori, jadi risiko
   ini NYATA. Mitigasi cepat: tulis event log ke disk per trick; jangka
   panjang Redis + snapshot per trick.
3. AI latency: tidak relevan untuk Tier A (sinkron, murah).
4. Desync: dimitigasi karena setiap perubahan mengirim snapshot penuh,
   sehingga client selalu pulih pada update berikutnya. Hash state
   berkala: [BELUM].
5. [BARU] Secret & kredensial: SESSION_SECRET acak per start membuat
   token reconnect tidak berlaku setelah restart; setel lewat env.
   JWT_SECRET lama yang pernah ada di repo sebaiknya dirotasi.
6. [BARU] Penumpukan timer: tiap Room memegang timer; pastikan destroy()
   dipanggil saat room kosong (sudah lewat onEmpty/roomIdleMs 10 menit).
7. [BARU] Tidak ada rate limit: satu klien dapat membanjiri aksi.
   Tambahkan batas per koneksi sebelum dibuka ke publik.
